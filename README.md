# 博物馆单张展签排版工具（Museum Label Typesetter）

一个用于排版**单张**博物馆展签的 Web 工具：输入标题、中文说明文字、可选的**英文译文**
与展签物理尺寸（毫米），浏览器实时预览，并可直接打印或导出为与预览**同换行、同物理尺寸**的 PDF。

- 填写英文译文即进入**中英对照双栏模式**：标题横跨整签，中文原文与译文左右并列；译文留空保持单栏
- 可选**中文修订对照**：填写不超过 300 字的修订稿后，按 Unicode 字符求最短增删对齐并标出新增/删除片段；
  原稿与修订稿分别按当前尺寸与英文译文排版，对比字号、中文行数与能否容纳；选定一版作为成品，
  差异标记只在屏幕上显示，不进入打印
- **中文专名保护表**：每行一个不可断行的词（最多 20 个、每个 1～12 个 Unicode 字符），
  在标题与中文正文中逐段最长匹配；命中词内部不可断行，边界仍遵守标点避头尾规则，
  最小字号下仍超宽时给出该词与所需宽度并禁用打印；原稿与修订稿共用同一张表
- 后端：Node.js + Express（仅提供静态页面）
- 前端：原生 JavaScript / CSS，无构建步骤、无前端框架
- 排版算法：按 Canvas **实际字宽**逐字/逐词测量 + 动态规划断行
- 无数据库、无第三方账号、无外部 API

## 一条命令启动（Docker Compose）

```bash
docker compose up --build
```

然后浏览器打开：

```
http://localhost:3000
```

首次启动会在容器内自动执行 `npm install`（依赖随启动安装，不预装在镜像中），稍等数秒即可。

> 如果本机使用的是独立 `docker`（无 Compose 子命令）：
>
> ```bash
> docker build -t museum-label-typesetter .
> docker run --rm -p 3000:3000 museum-label-typesetter
> ```

## 不用 Docker 的本地运行方式

需要 Node.js ≥ 18。

```bash
npm install        # 安装唯一运行时依赖 express
npm start
```

访问 http://localhost:3000 。

## 必要配置（环境变量）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `3000` | 服务监听端口。改端口：宿主机侧改 `docker-compose.yml` 的 `"3000:3000"` 左侧；容器内监听改环境变量 `PORT` 并同步右侧。 |
| `HOST` | `0.0.0.0` | 监听地址，容器内保持默认即可。 |

例如用本机 8080 端口：

```bash
PORT=8080 npm start                     # 本地直跑
docker run --rm -p 8080:3000 museum-label-typesetter   # Docker
```

## 使用方法

1. 左侧输入**标题**与**中文说明文字**（正文内回车可分段；中文里可直接夹 English 单词）。
2. 如需中英对照，在**英文译文**框填写译文（同样支持回车分段）：
   - **填写译文** → 双栏模式：标题横跨整签，中文原文与译文在正文区左右并列，栏间距固定 6mm；
   - **译文留空（或仅空白字符）** → 保持现有单栏排版。
3. 可选：在**修订稿**框输入修订后的中文正文（不超过 300 字，超出自动截断）：
   - 对照区按 Unicode 字符求**最短增删对齐**（同代价时固定优先保留原文较早字符），
     绿色为新增、红色删除线为已删，段落的增删以 ↵ 标记；
   - 原稿与修订稿沿用当前尺寸与英文译文**分别排版**，对照表列出两版正文字号、中文行数与能否容纳及其变化；
   - 在「成品版本」中选择原稿或修订稿：右侧预览与打印只显示所选版，差异标记不进入打印；
   - 所选版排不下时对照区保留，状态与预览说明**超宽或超高**，打印按钮禁用；
   - 清空修订稿即恢复原有单稿模式。
4. 可选：填写**中文专名保护表**（在英文译文框下方）：
   - **每行一个词**，最多 **20** 个、每个 **1～12 个 Unicode 字符**；
   - **空行忽略**（只含空格的行也算空行），**重复词自动去重**（保留首次录入位置），
     含有空格、制表符等**换行以外空白**的行会报错，词超长或总数超限也会报错并禁用打印，直到修正；
   - 排版**标题与中文正文**时，在每个段落内**从左到右**识别保护词：
     同一位置优先匹配**最长**的词，长度相同按**录入顺序**，已匹配的字符不再参与后续匹配；
     **英文译文不参与保护**；
   - 命中的词在版面中**内部不可断行**（整体移动到下一行），词的**首尾边界仍遵守原有的标点
     避头尾规则**（如词首是开标点不会留在行尾、词尾是闭标点不会出现在行首），并继续由现有
     动态规划算法在 12–24px 中选择最大可容纳字号；
   - **原稿与修订稿分别排版但应用同一张保护表**；修改保护表后**实时重排**，预览与打印共用
     同一份断行结果；
   - 若某保护词即使在最小字号（正文 12px、标题约 16.8px）下仍超出行宽，预览区与状态行会
     **显示该词及所需宽度（mm）并禁用打印**——不会拆词、截断或压缩字号，请加宽标签或移除该词。
5. 输入展签**宽度 / 高度（毫米）**，合法范围 30–999mm × 20–999mm，内边距固定 8mm。
6. 右侧实时预览（屏幕上会自动缩放以适应窗口，仅为显示效果）。
7. 点击「打印 / 导出 PDF」，在系统打印对话框中选择打印机或「另存为 PDF」。
   纸张尺寸会被自动设为展签的毫米尺寸，**边距请选择「无 / 默认」**，缩放保持 100%，
   即可得到与预览换行、字号、物理尺寸完全一致的成品。

## 排版规则

1. **实际字宽**：所有字符宽度由 Canvas `measureText` 按当前字号、字体实测（带缓存），
   不是按“汉字全角、英文半角”的假设估算。
2. **英文单词不可拆**：连续拉丁字母/数字（含词内连字符、撇号，如 `state-of-the-art`、`don't`）
   作为整体移动到下一行。
3. **标点避头尾（kinsoku）**：
   - 闭标点（`。，、！？：；）》】”’…—·` 等）不出现在行首；
   - 开标点（`（《【「“‘` 等）不留在行尾；
   - 成对破折号、省略号不会被拆到两行。
4. **全局最优断行**：动态规划枚举全部可行断点，在所有放得进行宽的排法中
   **最小化非末行空白宽度的平方和**（与 TeX 段落断行思想一致），使各非末行尽量均匀填满；
   代价相同时取行数更少的排法。
5. **字号选择**：正文字号从 **24px 向下枚举到 12px**，取能同时满足行宽与总高度的
   **最大整数**；标题字号固定为正文的 1.4 倍、加粗，并按同样规则折行。
   **双栏模式**下标题横跨整签（按内容全宽折行），中英两栏按扣除 6mm 栏间距后
   **平分得到的实际栏宽各自独立断行**；字号为两栏**共享**——枚举两栏在该字号下
   都能排下（行宽）且总高度（标题 + 较高一栏）不超签高的最大字号。
6. **装不下即报错**：若 12px 仍超出高度，或存在在最小字号下都放不进行宽的内容
   （例如超长英文单词、超宽的专名保护词），预览区显示红色错误，且**绝不截断或压缩字号**，
   打印按钮禁用。错误信息会标明问题所在：
   - 超宽：指出是**中文原文栏**还是**英文译文栏**（或标题）及该栏实际栏宽；
     若超宽的是保护词，还会逐词列出**保护词文本与其在最小字号下所需的毫米宽度**；
   - 超高：指出**哪一栏较高**，并给出内容所需毫米数与可用毫米数。
7. **打印一致**：预览的断行结果由同一算法一次性算出并直接写入 DOM（预断行），
   预览与打印共用同一份断行结果与毫米尺寸；打印时沿用同样的行、同样的 px 字号与
   毫米容器；`@page` 尺寸在打印前被设置为标签宽×高，保证 1px = 1/96 英寸的物理换算一致；
   保护表的实时重排同样写入这份共享结果，因此**预览与打印的断行（含保护词位置）完全一致**。
8. **修订对照**：修订稿上限 300 字（按 Unicode 字符计，超出截断）；对齐为码位级
   **最短增删对齐**（仅插入/删除，等价于最长公共子序列），同代价时固定优先保留
   原文较早字符，结果确定唯一；对照仅针对中文正文，标题与英文译文不参与差异计算；
   差异标记只出现在屏幕对照区，打印输出始终只有所选成品版本。
9. **中文专名保护**：
   - 保护表每行一词（空行忽略、重复去重、含换行以外空白报错、1～12 个 Unicode 字符、最多 20 个）；
   - 匹配在每个段落内独立进行：从左到右贪婪扫描，同位置**最长优先**、同长按**录入顺序**，
     已匹配字符不再参与匹配；空格是天然屏障，保护词不会跨越空格；英文译文不做保护匹配；
   - 命中区间与英文单词一样作为**不可拆整体**参与动态规划：词内部不产生断点，
     词的首尾边界仍按其实际首/尾字符参与第 3 条的**避头尾**判断（开标点不留行尾、
     闭标点不出现行首、成对标点不拆行），其余断行代价与字号搜索规则不变；
   - 保护词在最小字号下仍超行宽时，整体作为超宽内容上报：显示该词及所需宽度，
     **禁用打印，不拆词、不截断**；
   - 原稿与修订稿各自排版但**共用同一张保护表**，标题与中文正文均应用。

## 项目结构

```
.
├── Dockerfile              # node:20-alpine，启动时 npm install
├── docker-compose.yml      # 单服务，默认映射 3000
├── package.json            # 唯一依赖：express
├── server.js               # Express 静态服务（/healthz 健康检查）
└── public/
    ├── index.html          # 单页界面（含修订稿、专名保护表输入与修订对照区）
    ├── css/style.css       # 界面样式 + 毫米级展签 + 打印样式
    └── js/
        ├── diff.js         # 修订对照：Unicode 字符最短增删对齐（无 DOM 依赖）
        ├── layout.js       # 保护表解析/匹配 + 分词 + 标点避头尾 + 动态规划断行（无 DOM 依赖，单/双栏共用）
        └── app.js          # 字宽测量、12–24px 字号搜索、单栏/中英双栏规划、保护表应用、两版对照、渲染、缩放、打印
```

## 说明与限制

- 本工具面向**单张展签**：一个页面对应一张标签，不做多标签拼版。
- 修订对照只比较中文正文；差异标记仅显示在屏幕对照区，打印输出始终只有所选成品版本。
- 专名保护只作用于**标题与中文正文**（含其中夹带的英文片段整体）；英文译文栏不应用保护表，
  保护词不跨越空格与段落；保护表非法（空白、超长、超量）时不进行排版并禁用打印。
- 双栏模式仅由**英文译文是否填写**控制：标题不随译文翻译，始终横跨整签；
  两栏共用同一正文字号与行高，不各自缩放；栏间距固定 6mm，暂不提供可调分隔线。
- 对齐方式为左对齐（展签常见排版），不做两端对齐拉伸字距。
- 字体使用浏览器/系统自带的宋体/衬线字体族，无需联网下载字体；
  不同系统的字宽可能有细微差别，断行会在打开页面的那台机器上按其可用字体实测计算，
  因此请在实际打印的机器上进行最终预览确认。
- 全部计算在本地浏览器完成，不向任何外部服务发送内容。
